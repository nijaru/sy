# sy 0.5 alignment audit

Repository-wide assessment of the `v0.5-architecture` branch against
`docs/architecture-0.5.md` (the target contract) and
`agent-context/ai/0.5-design-audit.md` (accepted design decisions).

This is a *current-state* record. Findings are evidence-based; each names the
execution path that proves it. Items marked **decision** need the user before
implementation. The actionable sequence lives in
`agent-context/ai/0.5-rewrite.md` ("Implementation order").

- Audited at: `1f6b625` (xattrs landed), PR #27.
- Method: module/reachability trace from the CLI (`src/main.rs` →
  `src/sync/session.rs` → engine/protocol/remote), plus direct inspection of
  the legacy stacks' entry points. Bisync internals, `transport/` and
  `streaming/` internals, and the benches were inspected only at their
  boundaries; findings there are labelled as such.
- Not re-litigated: the accepted decisions in `0.5-design-audit.md`
  (rooted-filesystem model, bisync three-way semantics, compression set, delta
  policy, object-store capability shape). This audit reports *conformance* to
  them.

## Summary

The new core is coherent and well-tested: one ordered reconciler, one planner,
one scheduler, one safety-ordered controller shared by push/pull/local, a
bounded v3 protocol with adversarial coverage, and descriptor-rooted
confinement. The remaining risk is not the new core — it is that two
architectures are still **live reachable** from the CLI, and one of them
(bisync/v2 transport) contradicts accepted safety decisions and currently
blocks `sy-remote` removal.

| # | Finding | Severity | Blocking |
|---|---------|----------|----------|
| F1 | Two live architectures; legacy stacks reachable from the CLI | structural | item 7 |
| F2 | `--bidirectional` contradicts the accepted bisync design **and** keeps `sy-remote`/v2 alive | structural + safety | item 7, needs decision |
| F3 | Legacy remote root interpolated into the SSH command line (confinement invariant) | safety | item 7 |
| F4 | `Endpoint` capability contract is local-only; remote is a bespoke path | design risk | object-store item |

| F7 | Release gates (musl, Miri, benchmarks, all-feature tests) unmet | process | release |
| F8 | Design/alignment docs not linked from `AGENTS.md` | discoverability | — |

## F1 — Two live architectures; legacy stacks are CLI-reachable

**Locations**
- `src/sync/session.rs:107` `direct_local()` → `reconcile::run_local_sync` when
  `v3_local::legacy_fallback_reason` is set.
- `src/sync/session.rs:277` `streaming_push()` → `streaming_push_legacy()` when
  `v3_push::legacy_fallback_reason` is set.
- `src/sync/v3_push.rs:34` / `src/sync/v3_local.rs:38` — the clauses are
  `config.preserve.acls || config.preserve.flags`.
- `src/main.rs:586` (`--watch`), `:613` (`--bidirectional`), `:133` (`--server`).

**Evidence.** `-A/--preserve-acls` and `-F/--preserve-flags` are accepted by the
CLI (`src/cli.rs:301`, `:305`). For a local sync they route to the legacy
`OrderedReconciler`-in-`reconcile.rs` + `TaskExecutor` path
(`src/sync/reconcile.rs:68`, `src/sync/executor.rs`). For a push they route to
the v2 stack: `transport::server::ServerSession::connect_ssh`
(`src/sync/session.rs:295`) + `streaming::StreamingSync` (`:309`). That path
uses the whole-tree `sync::scanner` `FileEntry` model, not the lean `Entry`
stream.

So `cargo build` still produces two engines, and a single flag switches which
one the user gets. That is exactly the "0.5 is not done while two
architectures remain" condition in the architecture doc.

`--server` (`src/main.rs:133` → `sy::server::run_server`,
`src/server/mod.rs`) is the v2 remote agent entrypoint, still live on the same
binary as `__serve`.

**Consequence.** Invariant drift: fixes proven on v3 (identity revalidation,
transactional staging, exact delete preflight, bounded queues) do not apply on
the fallback path. It also keeps the whole v2 dependency surface reachable.

**Bounded correction.** Finish the item-6b preservation cluster on the unified
executor (ACLs, then BSD flags) — that alone removes the local *and* push
fallback clauses. Then delete the legacy local path and the v2 push path. No
CLI-accepted configuration should select a second engine.

## F2 — `--bidirectional` contradicts accepted design and blocks removal (**decision**)

**Locations**
- `src/main.rs:613-763` — bisync dispatch.
- `src/main.rs:742` — `bisync::BisyncEngine::new(source_transport, dest_transport)`.
- `src/bisync/engine.rs` — orchestration over `crate::transport::Transport`.
- `src/bisync/classifier.rs` — legacy change classification.
- `src/bisync/engine.rs:28` — `BisyncOptions::default()` sets
  `conflict_resolution: ConflictResolution::Newer`.
- `src/transport/ssh.rs:288,315` — `remote_binary_path: "sy-remote"` and the
  `sy-remote` deployment path.
- `src/engine/bisync.rs`, `engine::bisync_state`, `engine::bisync_store` — the
  accepted timestamp-free semantic core.

**Evidence.** `0.5-design-audit.md` states the legacy classifier is not a 0.5
foundation (it can declare two files equal from size+mtime, and can miss
same-size edits), that the semantic core in `engine::bisync` intentionally has
no timestamp inputs, and that default conflict behavior must **not** be
newer-wins. The CLI path does the opposite of all three, and its remote leg
deploys `sy-remote` via `SshTransport` — so it is one of the reasons
`src/bin/sy-remote.rs` cannot be deleted.

**Consequence.** A user-visible feature carries rejected safety semantics, and
it structurally blocks the item-7 deletions.

**Options (need user authority).**
1. *Rebase*: reimplement `--bidirectional` on `engine::bisync` +
   `engine::bisync_store` with conflict-preserving defaults, then delete
   `src/bisync/*` and the `Transport`-based legs.
2. *Defer with a loud gate*: keep the flag but refuse it on remote paths /
   mark it experimental until rebased.
3. *Kill*: remove `--bidirectional` and `src/bisync/*` before 0.5.

No unilateral choice is safe: (1) is real work, (2)/(3) change user-facing
behavior. This is the "bisync keep/kill" decision the rewrite context already
flagged.

## F3 — Legacy remote root is interpolated into the SSH command line

**Location.** `src/transport/server.rs:40-44`:
`cmd.arg("sy").arg("--server").arg(remote_path)`.

**Evidence.** The architecture and `AGENTS.md` both state "No user filesystem
path belongs in the SSH shell command; roots and relative paths are protocol
data." The v3 path obeys this (`SessionOpen`), and `0.5-rewrite.md` already
records the v2 *pull* violation. The v2 **push** violation is still live and
reachable via `-A`/`-F` pushes (F1), and `src/transport/ssh.rs` has the same
shape for `sy-remote`.

**Consequence.** A path containing shell metacharacters is user input reaching
the remote shell. This is a security invariant, not just architecture, and
should be tracked as such until the path is deleted.

**Bounded correction.** Deleted by F1/item 7. Do not patch v2; if the fallback
must survive longer than expected, that is an argument to prioritize removing
it, not to harden it.

## F4 — The `Endpoint` capability contract is local-only

**Locations.** `src/endpoint/mod.rs` (trait), `src/endpoint/local.rs:165` (the
only implementor). Remote behavior lives in `src/remote/{push,pull,local_executor}.rs`
plus `RootedFs`, not behind `Endpoint`.

**Evidence.** `impl Endpoint for` appears exactly once. `Endpoint`'s
demand-driven hooks (`read_xattrs`, `read_acl`, `read_bsd_flags`,
`native_path`, `begin_write`, …) are exercised only by local transfers; the
remote side re-expresses the same operations as protocol RPCs.

**Assessment.** This is not yet a defect — the shared `SyncPlanExecutor`
controller means the three directions do share ordering and safety semantics,
which is the outcome that mattered. It is a *design risk* for the object-store
item: the architecture's "capabilities, not endpoint branches" and a single
endpoint contract are only half-realized, and `capabilities()` is effectively
advisory (`RemotePushExecutor` never consults it).

**Recommended direction (not yet scheduled).** When object endpoints start,
decide one owner: either promote the remote/object operations behind
`Endpoint` (with the remote handle as the implementation), or formally drop
the trait as local-only and document the executor + capability model as the
real abstraction. Two capability vocabularies (`endpoint::Capabilities`,
`protocol::CapabilitySet`) must not both be treated as authoritative.

## F5 — Dead scaffolding still compiled and tested

**Evidence (reachability).**
- `SyncEngine` (`src/sync/mod.rs:45`): referenced only by `src/sync/watch.rs`
  and tests. `main.rs` uses `sync::watch_session::{WatchSession}` (`:594`), and
  `WatchMode` in `src/sync/watch.rs` has no non-test caller.
- `StrategyPlanner` (`src/sync/strategy.rs:36`): only `SyncEngine` and its own
  tests.
- `Transferrer` (`src/sync/transfer.rs`): only `SyncEngine`.
- `src/sync/scale.rs` (`FileSetBloom`): only `SyncEngine`.
- `sync::scanner` (`FileEntry`/`Scanner`): only legacy stacks (F1) + bisync +
  `src/bin/sy-scan.rs` + `src/bin/sy-remote.rs`.
- `src/resume.rs`: only `transport/ssh.rs` + `SyncEngine`.
- 122 `#[allow(dead_code)]` sites, concentrated in the condemned stacks.

`0.5-rewrite.md` already notes `SyncEngine::sync` is CLI-unreachable. The audit
confirms it is **test-only**, which makes `StrategyPlanner`, `Transferrer`,
`scale`, and `watch.rs` removable together with it.

**Consequence.** Build time, review noise, and ambiguity about what is
authoritative. It also makes "delete obsolete tests" harder because the
dead modules own a large fraction of the suite.

**Bounded correction.** Delete in item 7 with the stacks, and confirm by
reachability rather than by name: `rg 'SyncEngine|StrategyPlanner|Transferrer|FileSetBloom'`
must return no non-test callers before removal.

## F6 — Duplicated representations across old/new stacks

**Evidence.**
- Two `SyncStats`: `src/sync/stats.rs:5` (live, user-facing) and
  `src/streaming/channel.rs:218` (v2), bridged in `session.rs:472`.
- Two `TransferResult`: `src/endpoint/transfer.rs:45` (live) and
  `src/transport/mod.rs:31` (legacy).
- `src/remote/transfer.rs:36` `TransferSummary` vs
  `src/remote/push_controller.rs:313` `RemotePushSummary` vs
  `src/sync/stats.rs` — three summary shapes for one run, reconciled by hand in
  `summary_stats` (`v3_push.rs`).
- Two delta implementations: `src/delta/` (legacy) and
  `src/transfer/delta.rs` (v3), with a live cross-dependency —
  `src/endpoint/transfer.rs:240` calls `crate::delta::estimate_change_ratio`
  for the reflink-vs-whole-copy heuristic.
- Two capability vocabularies (see F4); two compression modules
  (`src/compress/` detection + `src/engine/compression.rs` policy).

**Assessment.** Expected mid-rewrite, and the live cross-dependency in
`endpoint/transfer.rs` is the only one that constrains deletion order: the new
local transfer layer still imports the legacy delta heuristic, so `src/delta/`
cannot be deleted until that ratio estimate is moved to `src/transfer/delta.rs`
(or inlined). Record this so item 7 is not surprised.

## F7 — Release gates and verification coverage

**CI (`.github/workflows/ci.yml`).** Seven jobs: fmt, clippy
(`--all-features`), audit, deny, man-page, test Linux, test macOS. `cargo test`
runs **default features only**, so `acl`, `s3`, `gcs`, and `watch` code is
compiled but never exercised semantically.

**Release (`.github/workflows/release.yml`).** Builds `aarch64-apple-darwin`
and `x86_64-unknown-linux-gnu` only. No musl, no static-verification step.

**Gates in `architecture-0.5.md` not yet met.**

| Gate | State |
|------|-------|
| static musl x86_64/aarch64 | absent |
| Miri over unsafe/path/reflink code | not wired |
| representative benchmarks before release | benches exist, not run in CI |
| all-feature semantic tests | default features only |
| interrupted-transfer survival tests | covered per-file on v3; not on the v2 fallback |
| delete-replay destination identity validation | `execute_delete` removes by path only (`remote/push.rs`, `remote/pull.rs`, `local_executor.rs`) |
| transactional directory type transition | still `TransactionalDirectoryReplace` refusal on all three executors |
| namespace/case collision preflight | absent |
| parent-FD caching for the rooted resolver | not implemented (design-audit recommendation) |

**Assessment.** The *semantic* core is well covered (protocol adversarial
tests, confinement escape tests, delete-threshold tests, controller ordering
tests). The gaps are (a) release/process gates and (b) three accepted-but-
deferred safety features. None of these are regressions; they are the explicit
"not yet" list and should stay visible until closed.

## F8 — Documentation discoverability

`AGENTS.md` ("For AI Agents") sends a fresh session to
`docs/architecture-0.5.md` and `agent-context/ai/0.5-rewrite.md`.
`agent-context/ai/0.5-design-audit.md` — which holds *accepted decisions* that
constrain bisync, compression, delta, and object stores — is not linked, and
neither is this audit. A fresh session can therefore re-open decisions that
were already made.

**Bounded correction.** Add both audits to the `AGENTS.md` read path and cross-
link them from `0.5-rewrite.md`.

## What already works and should be preserved

- **Engine core** (`src/engine/`): `domain`, `reconcile`, `planner`,
  `scheduler`, `delete_plan`, `plan_journal`, `finalize_journal`,
  `ignore_scope`. One owner per decision; bounded; well-tested.
- **Protocol v3** (`src/protocol/`): fixed header, hard 1 MiB payload bound
  validated before allocation, native component paths, version/capability
  negotiation, adversarial + proptest coverage.
- **Rooted confinement** (`src/rooted_fs.rs`, `rooted_fs/scan.rs`): held root
  descriptor, no-follow component walk, descriptor-based reads/writes/metadata/
  hardlink/xattr, escape and root-swap tests.
- **Unified controller** (`src/remote/push_controller.rs`): one safety-ordered
  loop (preorder dirs, bounded concurrent leaves, reverse deletes, journal-owned
  finalize) with three executors; the hardlink and xattr slices landed once
  across all three.
- **Transactional staging + BLAKE3** on push/pull; staged-verify-before-commit.
- **Checkpoint discipline**: every push CI-green on all seven jobs.

## Prioritized alignment roadmap

Dependencies are strict unless noted. Verification for each item is the
smallest check that proves the ownership moved.

**P0 — finish item 6b (removes F1's fallback clauses).**
1. ACLs (`-A`, `acl`-gated): bounded RPC + fd-confined `RootedFs` + executor
   mirroring, reusing the xattr shape. → drop `acls` from the three
   `legacy_fallback_reason`s.
   *Verify*: `-A` local/push/pull stay on v3; E2E per direction; `cargo test --all-features`.
2. BSD flags (`-F`, macOS-only): same shape, single `u32`.
   *Verify*: same, plus a non-macOS loud refusal.
3. Delete `v3_push/v3_pull/v3_local::legacy_fallback_reason` and
   `reconcile::run_local_sync` reachability once both above land.
   *Verify*: no CLI-accepted config selects the legacy local path.

**P1 — bisync decision (F2, needs user).** Choose rebase / gate / kill.
*Verify*: whatever is chosen, `--bidirectional` no longer contradicts the
accepted conflict semantics, and `sy-remote` is no longer required by any path.

**P2 — item 7: delete the condemned stacks (F1/F3/F5/F6).**
Order: (a) move `estimate_change_ratio` off `src/delta/`; (b) remove
`src/bin/sy-remote.rs` + `src/transport/` + `src/streaming/` + `src/server/` +
`--server`; (c) remove `SyncEngine`/`StrategyPlanner`/`Transferrer`/`scale`/
`watch.rs`/`resume.rs` and the `Transport`-based bisync legs; (d) unify the
duplicate summary/stat shapes that remain; (e) delete obsolete tests.
*Verify*: `rg` reachability returns empty; `cargo build --all-features` and
`cargo test --all-features`; CLI smoke for local/push/pull.

**P3 — accepted-but-deferred safety work (F7).**
- Destination-identity validation on delete replay (all three executors).
- Namespace/case-collision preflight before mutation.
- Transactional directory type transitions (replace the
  `TransactionalDirectoryReplace` refusal).
- Parent-FD caching in the rooted resolver, only if benchmarks justify it.
*Verify*: targeted tests per item; delete tests reuse the existing
identity-token fixtures.

**P4 — item 8–10 (F7/F8).**
- `usage-rs` CLI migration; generated help/man/completions.
- Edition 2024 migration on the cleaned baseline.
- `cargo machete` + dependency cleanup.
- musl static builds (`x86_64`, `aarch64`) + CI static check; optionally the
  bootstrap layer.
- CI/pipeline expansion: Miri, all-feature semantic tests, benchmark job.
- Update docs/discovery links (F8) when the above land.

## Open question

Bisync (P1) is the only item that cannot proceed on engineering judgment alone:
it is a user-facing behavior and safety decision. Everything else is authorized
by the standing rewrite direction.
