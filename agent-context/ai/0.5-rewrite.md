# sy 0.5 rewrite context

This file is the canonical implementation context for the `v0.5-architecture` branch. Read `docs/architecture-0.5.md` first for the target design, then use this file for current state and sequencing.

## Direction

0.5 is a ground-up internal rewrite. Do not preserve 0.4 internals, wire compatibility, module structure, transport APIs, log strings, or tests that encode obsolete implementation details.

Preserve user-facing behavior only when it is useful and intentional. Data-safety semantics take precedence over compatibility.

The target is:

```text
EntryStream -> Reconciler -> SyncOp -> Planner -> WorkItem -> Scheduler
                                      |
                                      +-> Local / Remote / Object endpoint capabilities
```

One binary (`sy`) acts as client and private remote agent (`sy __serve`). `sy-remote` must disappear before 0.5.

## Required Rust guidance

Use the user's `nijaru/dotfiles` skills:

- `dot_agents/skills/rust-cli/SKILL.md` when the CLI migration begins.

Important consequences:

- stay on the repository's existing runtime unless the architecture requires otherwise;
- bounded channels/backpressure;
- typed library errors and contextual application errors;
- no recoverable `unwrap()`/`expect()` in production paths;
- every unsafe block has a `// SAFETY:` invariant comment;
- run `cargo fmt --check` and `cargo clippy --all-features --all-targets -- -D warnings`;
- use `cargo deny`, audit, and Miri where relevant;
- when the CLI is replaced, use the `usage-rs` facade rather than building new clap infrastructure.

The branch currently remains Edition 2021 while substantial legacy code still compiles. Moving to Edition 2024 is reasonable after the legacy stack is deleted and should be done as an explicit reviewed migration, not opportunistically.

## Current 0.5 foundations

### Engine domain

`src/engine/domain.rs` owns new engine-native types independent of legacy `FileEntry`/`SyncTask`:

- canonical non-empty `RelativePath`;
- nanosecond `Timestamp`;
- opaque 32-byte `EntryIdentity` for scan/open/commit race detection;
- lean `Entry` and `EntryKind`;
- semantic `SyncOp` and `SkipReason`.

Do not put transfer strategy, xattrs, ACLs, sparse extents, or block signatures into the base `Entry`.

### Ordered reconciliation

`src/engine/reconcile.rs` is the new bounded merge layer:

- at most one source and one destination entry are retained;
- it emits `SourceOnly`, `Matched`, and `DestinationOnly` relationships;
- source and destination streams must be strictly ordered;
- duplicate/out-of-order entries are rejected at the trust boundary instead of silently accepted.

The compatibility `src/sync/reconcile.rs` is still the active local session path until endpoint adapters are migrated, but it is scaffolding only.

### Semantic planning

`src/engine/planner.rs` decides what change is required without choosing a transfer mechanism. It supports quick, size-only, checksum, and always-changed comparison modes. Checksum mode returns `NeedContentComparison` when sizes match so the controller can request hashes/signatures only when needed.

Entry-kind changes become semantic `SyncOp::Replace`; execution safety belongs to the transaction layer, not the comparison policy.

### Exact bounded deletion

The active local compatibility reconciler now uses `src/engine/delete_journal.rs` as an exact reverse-readable temporary spool. There is no Bloom-filter membership check in the active local deletion path.

Delete preflight merge:

1. consumes complete ordered source/destination scans without mutation;
2. counts exact eligible/candidate entries;
3. records destination-only candidates;
4. records protection markers for candidate directories containing source-backed/excluded descendants;
5. enforces the delete threshold before mutation;
6. after successful non-delete work, replays records in reverse so children precede parents.

Directory removal is deliberately non-recursive during journal replay so a concurrent/protected child fails closed. The next deletion hardening step is to journal destination identity tokens as well as paths so a concurrently replaced path cannot be deleted after preflight.

### Non-directory type replacement

The local endpoint already stages regular files and symlinks in the destination directory and commits with rename. The compatibility planner now permits file↔symlink replacement in either direction and tests both cases. Directory↔non-directory replacement remains blocked until the new engine owns an explicit tree transaction/tombstone rollback sequence.

### Endpoint preservation work

Useful 0.5 pieces already implemented in the compatibility endpoint/executor path:

- streaming readers and staged writers;
- same-directory atomic regular/link replacement;
- demand-driven xattr/ACL/BSD flag reads/writes;
- exact xattr mirroring (including stale-attribute removal);
- preservation capability validation on both source and destination;
- metadata errors propagate rather than being warning-and-ignore paths.

Extended file metadata is still applied after the current regular-file byte commit, so it is not yet a fully staged transaction. The final transaction layer should apply metadata to staging whenever the backend permits it.

### Protocol v3 foundation

Protocol v3 lives separately under `src/protocol/`; do not evolve `streaming/protocol.rs` into it.

Implemented foundation:

- typed `ProtocolError`;
- fixed 12-byte frame header;
- hard 1 MiB frame payload bound validated before body allocation;
- typed frame kinds/flags and stream IDs;
- protocol version-range negotiation;
- capability bitset;
- client/server build and platform identity;
- adversarial/truncation/property tests;
- panic-free production frame decoder.

Relative paths are delimiter-free component sequences, not slash-delimited strings. The canonical wire representation is a bounded sequence of length-prefixed opaque native-name components. This is required so Unix byte names and Windows UTF-16LE names do not share fake separator-byte semantics. The protocol validates structure/bounds only; endpoint adapters validate platform-specific name semantics after platform negotiation.

`WirePath` for a root is still an opaque bounded native payload. Root/session-open semantics may move out of the initial hello if needed to make target-platform encoding negotiation cleaner; protocol v3 is not frozen yet.

## Pieces worth keeping / evolving

These branch components express useful 0.5 ideas, although they may move modules or change types:

- `src/endpoint/io.rs`: streaming readers and transactional staged writers.
- `src/endpoint/local.rs`: same-directory staging and demand-driven preservation metadata.
- `src/endpoint/local_scan.rs`: ordered bounded local scan concept.
- `src/endpoint/transfer.rs`: native whole copy, reflink patch, sparse copy, staged streaming strategies.
- `src/engine/domain.rs`, `planner.rs`, and `reconcile.rs`: new canonical semantic core.
- `src/engine/delete_journal.rs`: exact bounded destructive-plan spool.

Treat compatibility modules as source material, not APIs that must remain stable.

## Known problems to eliminate

### Split engines

`src/sync/session.rs` still dispatches local sync to the compatibility reconciler while SSH uses old `StreamingSync` v2. Remote endpoints must feed the same new `engine::reconcile::OrderedReconciler` and semantic planner.

### Legacy stacks

Before release, delete:

- `src/bin/sy-remote.rs`;
- `src/transport/`;
- old `src/streaming/` v2 once v3 is live;
- old `SyncEngine<T: Transport>` in `src/sync/mod.rs`;
- old `StrategyPlanner` in `src/sync/strategy.rs`;
- `src/ssh/connect.rs` and the homegrown SSH config parser once external OpenSSH is live;
- compatibility whole-tree scan APIs and duplicate state/stats representations.

### Scanner metadata cost

The compatibility ordered scanner no longer reads xattrs/ACLs eagerly, but still gathers fields not required by every sync. The final endpoint scanner should construct lean engine `Entry` values and request hardlink identity, sparse extents, xattrs, ACLs, flags, and hashes only when policy/transfer planning requires them.

### Directory transactions and metadata ordering

Directory↔non-directory replacement still needs a tree transaction. Directory permissions/mtime must be finalized after children (postorder); applying restrictive permissions or final mtime before child creation is incorrect.

### Source mutation

Scanning and transfer can still race source changes. Populate `EntryIdentity`, validate identity when opening the source, and validate again before destination commit. Retry or fail rather than commit a mixed snapshot.

### Name/collision semantics

Cross-platform sessions must preflight destination namespace semantics. Case-insensitive or normalization-insensitive destinations can collapse distinct source names (for example `A` and `a`). Detect collisions before mutation; never silently rename or overwrite one source entry with another.

### Root confinement

Lexical relative-path validation is not a security boundary. Local and remote filesystem endpoints should ultimately resolve relative to held root directory handles. Linux should prefer `openat2`/`RESOLVE_BENEATH`; macOS/other Unix should walk directory FDs with no-follow semantics.

### Protocol v2

Current v2 problems include destination-tree materialization, eager signatures, fixed 4096-byte blocks, materialized delta ops, UTF-8 paths, lexical confinement, and post-rename size-only verification. Do not repair v2; delete it after v3 cutover.

## Remote design

Use the external OpenSSH executable as transport. Do not keep `ssh2` in the final dependency graph.

Remote process launch:

```text
ssh -T user@host sy __serve
```

Do not put the remote filesystem path on the shell command line. The binary protocol carries the root/session-open request.

The remote agent must confine every operation to a held root directory handle. On Linux use `openat2`/`RESOLVE_BENEATH` style resolution; on macOS walk directory FDs with no-follow semantics.

## Next protocol milestones

- cheap ordered metadata messages using component-framed wire paths;
- same core reconciler consuming local and remote endpoint streams;
- explicit session/root-open semantics after platform negotiation if needed;
- on-demand adaptive signature streams;
- direct bounded `DeltaOp` production;
- staged remote reconstruction;
- sender/staged BLAKE3 comparison before commit;
- multiplexed streams controlled by scheduler budgets.

## Scheduler

Do not use a single file-count semaphore as the final resource model. Scheduler budgets should account for:

- active files;
- bytes buffered/in flight;
- metadata concurrency;
- hashing/compression CPU concurrency;
- network frame/write pressure.

A large transfer must consume more byte budget than a tiny file even if both count as one active file.

## Remote bootstrap / issue #26

Issue #26 asks for statically linked musl releases. Do not respond to the issue unless the user explicitly asks later.

The request fits the new design:

- one static `sy` binary can be copied to a remote and invoked as `sy __serve`;
- no separate `sy-remote` artifact;
- external OpenSSH removes libssh2/OpenSSL from the application's SSH implementation;
- target at least x86_64 and aarch64 Linux musl artifacts;
- release CI must verify the result is truly static.

Automatic bootstrap can follow protocol stabilization: try installed compatible `sy`, then upload/cache a trusted matching static agent only if needed.

## CLI direction

Do not spend significant time repairing clap/manpage infrastructure that will be deleted. Once engine/protocol boundaries are stable, migrate the user CLI to `usage-rs` v6 per the user's `rust-cli` skill. Generated usage specs should become the source for help/manpages/completions.

Retain familiar rsync-like syntax where useful, but remove misleading/redundant flags rather than carrying permanent compatibility debt.

## CI state

The goal before merging 0.5 is all checks green, not “green except baseline failures.”

Current ground-up work has repeatedly held all-features Clippy green once mechanical format issues are applied. The file↔symlink test regression on Linux/macOS was an interim planner restriction and has been corrected with explicit two-direction coverage.

Cargo audit/deny and the old manpage gate remain red from the legacy dependency/CLI stack. Remove or update their causes as those stacks are replaced rather than preserving obsolete infrastructure solely to make the interim branch green.

## Definition of done

0.5 is not done while two architectures remain. The release contains one coherent engine and one binary, with old internals physically removed and realistic CI/benchmarks demonstrating correctness, bounded resource use, transactional safety, and competitive performance.
